- 规则入口：[`2026-07-23-rmuc-rules-digest.md`](2026-07-23-rmuc-rules-digest.md)

## 1. 目标与边界

Phase 1 要建立一个可训练、可测试、可替换物理后端的 RMUC 闭环：

1. 用纯 Torch 实现唯一的裁判真值层和轻量运动学环境。
2. 用 Isaac Lab `DirectMARLEnv` 提供批量场景、传感器/可视化接口和后续物理升级路径。
3. 两个后端消费同一动作、几何事件和随机样本，并通过逐步一致性测试。

纳入战斗、热量、功率、经济、升级、存活、建筑、增益点、能量机关、飞镖、雷达、兵种特殊机制、比赛状态机和胜负判定。机械抓取、完整弹道/刚体接触、详细违规判罚与实车部署延后；科技核心操作先用可中断的区域有限状态机 `[SIM]` 近似。

## 2. 架构

```text
policy / scripted opponent
           │ heterogeneous actions
           ▼
┌───────────────────────────────────────────────┐
│ Torch World 或 Isaac Lab Adapter              │
│ 运动学、区域/LOS、装甲投影、射击与接触事件    │
└──────────────────────┬────────────────────────┘
                       │ geometry + events
                       ▼
┌───────────────────────────────────────────────┐
│ rm_referee（纯 Torch，唯一规则实现）           │
│ combat → heat/power → economy/upgrade →       │
│ survive → objectives/roles → fsm/outcome      │
└──────────────────────┬────────────────────────┘
                       │ state/events/reward inputs
                       ▼
              observations / rewards / done
```

`rm_referee` 禁止导入 Isaac、Omniverse 或环境包装代码。Isaac Lab 只产生几何事实并同步场景，不拥有第二套伤害、经济或胜负逻辑。

## 3. 权威状态与接口

状态采用批量 SoA 张量；`E` 为环境数：

```text
unit_state: [E, 16, C]
  红/蓝各 8 槽：
  英雄、工程、步兵3、步兵4、空中、哨兵、基地、前哨站

armor_state: [E, 16, A, C_armor]
  装甲朝向、可见性、最近一次被 17/42mm 接受的时间

team_state: [E, 2, C_team]
  金币、按队累计的购买量、科技核心、飞镖、雷达、增益

match_state: [E, C_match]
  阶段、剩余时间、随机种子/计数、胜者与终止原因
```

空中单位保留动作和支援状态，但其 HP、受击、回血和复活通道始终被掩码。允许发弹量属于“机器人 × 弹种”；只有金币兑换累计上限属于队伍。立即复活次数也按机器人维护。

核心接口：

```python
state, events = referee.step(state, rule_inputs, random_tape, dt=0.1)
world, rule_inputs = backend.step(world, actions, substeps=6)
obs = observation_builder(state, world, visibility)
```

官方热量与功率均以 10Hz 结算，所以裁判步长固定为 `0.1s`。运动学/Isaac 默认 `1/60s` 子步；策略步长是 `0.1s` 的整数倍，默认 `0.2s`。

## 4. 裁判流水

每个 0.1 秒裁判 tick 采用固定因果顺序：

1. 校验角色、目标、锁定状态、弹量和射击窗口，生成实际射击事件。
2. 对射击事件增加热量、扣除该机器人的允许发弹量。
3. 用装甲几何与命中模型生成候选受击；按“单块装甲 × 弹种”的 50/200ms 检测间隔过滤伤害。
4. 结算普通/暴击/增益伤害、42mm 屏蔽、无敌和建筑保护。
5. 结算热量锁定、60J 功率缓冲和 5 秒底盘断电。
6. 更新金币、兑换、经验/等级、底盘能量和角色特殊机制。
7. 更新脱战、回血、复活读条、虚弱、建筑、增益点与任务目标。
8. 推进能量机关、飞镖、雷达、比赛阶段并执行胜负阶梯。

50/200ms 是装甲受击的 refractory window，绝不能截断实际发射数、热量或弹量。

## 5. 已纠正的规则约束

| 模块 | Phase 1 必须实现的语义 |
|---|---|
| 热量 | `Q0<Q1<Q2` 临时锁定并断图传；`Q1≥Q2` 永久锁定；不扣血 |
| 功率 | 60J 缓冲，10Hz 扣减；`Z≤0` 底盘断电 5 秒；不扣血 |
| 弹量 | 每台机器人独立；17mm/42mm 金币购买上限分别为 1000/100 发每队 |
| 超发 | 不扣血；42mm 超发触发对方装甲的 42mm 伤害屏蔽 |
| 复活 | 读条复活为 10% HP、虚弱、最长 30 秒无敌；立即复活为 100% HP |
| 基地 | 前哨站存活时无敌；HP≤2000 展开护甲，但展开本身不减伤 |
| 雷达 | 先更新连续量 `x`，再做 `P += x`，不是直接固定增量 |
| 空中 | 不受普通攻击/撞击，不回血、不复活，只在支援期间视为存活 |

胜负在时间耗尽或任一基地被击毁时统一结算：依次比较基地 HP、前哨站击毁历史/HP、全队攻击伤害、存活机器人总 HP。不得把“基地先到 0”写成绕过平分阶梯的特殊分支。

## 6. 战斗与命中

Phase 1 不做逐弹刚体仿真。后端提供射手、目标、弹种、时间戳、LOS、射线与装甲相交信息；`HitModel` 只负责规则未定义的不确定性：

```text
p_hit = p_aim(range, angle_error, projected_armor_area, los)
        × p_calibration × p_motion
```

距离衰减、瞄准噪声、小陀螺效果、雷达漂移和不完整飞镖识别均为 `[SIM]` 参数。前哨站旋转优先通过真实装甲朝向和投影面积表达，不直接写一个“高 dodge”规则。采样输入由 `RandomTape` 显式传入；单测和双后端对照使用相同样本，避免隐式全局 RNG。

高层射击目标为 9 类：

```text
敌方英雄、工程、步兵3、步兵4、哨兵、
敌方基地、敌方前哨站、己方能量机关、无目标
```

空中不是普通受击目标；能量机关也不是敌方建筑。英雄只能发射 42mm，工程无发射机构，42mm 与飞镖不能激活能量机关。

## 7. 双后端

### 7.1 Torch World

- 全批量 2.5D 运动学：位置、朝向、速度、碰撞投影和区域占领。
- 解析场地 primitive + 栅格/SDF 完成边界、LOS 和路径代价。
- 解析装甲平面完成射线相交、暴击区和受击模块编号。
- CPU 支持 `E=1` 调试，CUDA 支持大批量无渲染训练。

### 7.2 Isaac Lab Adapter

- 使用 `DirectMARLEnv` 管理并行环境、资产、传感器和生命周期。
- Phase 1 由运动学控制器写入根状态；不开启会改变比赛语义的复杂刚体弹道。
- 从场景读取姿态/接触/遮挡，转换为与 Torch World 相同的 `rule_inputs`。
- 从 `GameState` 回写 UI、材质和可视化，不在 adapter 内重算规则。

同一初态、动作序列、几何事件和 `RandomTape` 下，两端的裁判状态必须逐 tick 完全一致；运动轨迹在声明的数值容差内一致。

## 8. 异构动作与观测

- 英雄/步兵/哨兵：导航目标、9 类射击目标、开火门、小陀螺/姿态；英雄另有部署动作。
- 工程：导航、占领、取件/装配/重建操作。
- 空中：3D 导航、17mm 开火、支援/返航。
- 飞镖：目标模式和发射时机。
- 雷达：标记目标、反制空中、信息波操作。

非法动作由规则生成 action mask；策略输出先经过 deterministic controller，再变成底盘/云台/发射机构命令。观测只暴露本队裁判信息和传感器可见量，隐藏真值留在 critic 或评估通道。奖励由事件流构造，不写回裁判核心。

## 9. 验证

1. **规则单测**：每个表格边界和状态迁移均有 `E=1` 精确断言。
2. **性质测试**：HP/热量/缓冲范围、建筑保护、空中掩码、资源守恒和胜负阶梯。
3. **双后端契约测试**：固定几何事件与随机带，逐 tick 对比全部规则张量。
4. **回放验证**：记录事件驱动模式应精确复现可观测状态；1Hz 数据缺少逐发目标归因时，只验证时序、资源、结果和队伍级统计，不承诺逐机器人随机伤害精确相等。
5. **性能门槛**：在目标 GPU 上对 1024/4096 环境做 profile，禁止逐环境或逐单位 Python 循环。

回放胜者一致只能证明某些可观测结果一致，不能单独证明所有规则正确。官方表格边界测试和模块不变量仍是硬门槛。

## 11. 待官方信息或标定收敛

- 常规命中、小陀螺收益、雷达漂移、飞镖不完整覆盖概率。
- 场地图未定义的坐标原点/轴向和起伏路凸起高度。
- 工程取件/装配的 Phase 1 停留时间与中断条件。

这些未决项目必须在配置和实验报告中显式标为 `[AMB]` 或 `[SIM]`，不能写入“官方常量”表。热量边界不属于未决项：项目固定使用 `Q1≥Q2`。
